# Doc Generator

Open https://www.nxflo.com/admin.html and sign in as the configured owner. The Doc Generator tab saves settings in the private SQLite database in the `nxflo-bms-data` volume. Settings and generated files survive deployments. The selected tab and owner session survive refresh. Owner authentication expires after 30 days of inactivity; sign out revokes the browser session.

## Form and output

Topic & brief accepts research text, references, YouTube links, DOI citations and questions together. Up to 2,000,000 Unicode characters are preserved, including whitespace. A live word/character count updates on paste. Text over the limit stays in the box and must be shortened before saving; the server rejects it rather than truncating it.

Fill form with AI completes blank company, title and research questions using the selected provider: the configured Databricks model or OpenRouter Luna Flex. Existing values are preserved for fine-tuning. Blank dates use the current Vancouver date and blank versions use 1.0. Uploaded sources are excluded from metadata autofill. The single Company logo area accepts drag-and-drop or keyboard/click upload. With a saved logo it shows only the image; click it or drop another image to replace it. Logos render on white in the admin, HTML preview and PDF. Prepared by is the cover attribution; there is no separate Created by field or line.

Clear form resets document details, research, source uploads, supporting images and technical options after confirmation. It preserves the selected provider, company name, company logo, website, saved team contacts, selected team, document history and any active generation.

Start generate creates an immutable configuration snapshot. A separate LangGraph worker collects sources, summarizes evidence in chunks, outlines chapters, drafts, reviews and rewrites, polishes, draws source-backed SVG charts, assembles HTML, and pauses at **Preview HTML & continue**. The Review HTML action appears directly beneath step 10. The owner can review the actual generated HTML inline, open it in a new tab, or download it. **Continue to PDF** explicitly approves that HTML and queues PDF export with WeasyPrint; completed research and model responses are reused. The `awaiting_html_review` checkpoint survives page reloads and worker restarts, and PDF downloads remain unavailable until export finishes. The workflow animation follows persisted stage events, rather than a timer simulation. Refresh or return to `/admin.html?job=<id>` to follow the same job. On desktop the form narrows while generation runs; on mobile progress moves above the form.

The capybara chef prepares ingredients during collection, summarizing and outlining, stirs during drafting/review/export, and celebrates when the output is ready. Failed/cancelled jobs pause the scene. Reduced-motion preferences disable movement. Active steps show a circular meter from actual completed source checks or model requests, plus an elapsed timer calculated from saved step events. Unknown operation progress uses a spinning arc without an invented percentage. Review and rewrite elapsed times include repeated passes; source checks include unavailable sources whose collection attempt has finished.

Generated reports use the Folio report template and design system (MIT licensed, pinned upstream assets in `portal_api/vendor/folio/`). The HTML embeds Folio’s base and report styles plus the Nexusflow brand/responsive adapter; the existing restricted WeasyPrint renderer produces the PDF from the same HTML. Report formatting requires no provider calls, remote fonts or Folio CLI subprocesses. Existing saved artifacts retain their original formatting; newly generated documents and revisions use Folio.

Generated reports begin with a branded Folio cover, followed by linked contents with actual PDF page numbers. Chapters begin on new pages, and print margins include company headers and page/total footers. Typography, chart captions, references and the revision register have dedicated print styles; downloaded HTML remains responsive. Source/editorial warnings are retained in an appendix near the end, alongside an AI-assistance disclosure, and remain visible in the admin review panel. Moving notes off the cover does not change the job's `needs_review` status or imply editorial approval.

Completed outputs are private PDF and standalone HTML downloads. Source/editorial warnings are shown in the workflow and document. A document with warnings is marked `needs_review` and remains downloadable. Review generated claims, quotations and conclusions before sharing. The HTML review uses the generated document after assembly; it is separate from the retired layout-only preview. Public article publication, scheduling and email delivery are not implemented; release date is cover metadata. Images come from the user's uploaded assets; graphics are themed takeaway panels and deterministic charts, not generated artwork.

Revise this document (or Revise document in history) loads a completed document for feedback. The feedback, selected original and formal revision summary are saved across refreshes. Generation supplies the existing manuscript and editorial feedback to the outline/draft stages and checks feedback in review/polish. Source citations are mapped to the new evidence list. The server assigns the next numeric version within the document family, including when revising an older branch; manual version edits cannot reuse a revision number. Earlier documents are preserved. Numbers are reserved on submission, so cancelled/failed jobs can leave gaps. Detailed feedback is not printed in the revision log; the separate formal revision summary is. A document-control table near the end records version, Vancouver revision date, preparer and change summary for the issue and its lineage. The latest 50 jobs appear in history; authenticated links to older files remain valid.

## Sources and evidence

The owner has authorized fetching reference pages/YouTube transcripts and sending the brief, extracted documents and collected source text to the selected Databricks or OpenRouter provider. The worker fetches public HTTP(S) references only, validates DNS addresses and redirects, and pins connections to validated public IPs. Private, loopback and link-local addresses are rejected. Downloads are bounded to 8 MB; fetched PDFs to 150 pages; source text/transcripts to 300,000 characters each. The complete original brief remains saved; source summaries are chunked and condensed to fit downstream prompts.

Collection permits 200 reference URLs, 50 YouTube links and approximately 8 million combined source characters. Extra, blocked or unavailable sources are retained in the source manifest with explicit warnings. Missing captions may require uploading a transcript. Uploaded documents support PDF, DOCX, TXT, Markdown and CSV: 8 MB/file, 10 files, 80,000 extracted characters/file, 240,000 combined. Scanned PDFs require OCR before upload. Logos and up to four illustrations accept PNG/JPEG/WebP up to 2 MB each.

Optional web research uses Luna Flex and the OpenRouter web plugin independently of the selected writing model; web charges can apply. Search citations become additional references. The report labels the user's brief and AI web notes appropriately. Review checks unsupported claims against evidence notes; this is assisted review, not independent fact verification. Charts require structured numeric data plus matching exact source excerpts. Unverifiable chart data is omitted with a warning. When charts are enabled, prompts aim for 1–2 charts or graphs per 1–2 body pages and receive bounded original numerical excerpts. Valid charts are preserved through editing; insufficient verified chart coverage is reported as an evidence limitation rather than filled with invented data.

## Models, review and cost

One selected model covers summarizing, outlining, drafting, review and final polish by default. Advanced reveals separate summarizing, drafting/review and polish models. The compact matrix is ranked by input then output price; clicking a row applies that model to all stages. Prices and estimates update immediately when selections change. Refresh prices retrieves the public OpenRouter catalog.

Select **Databricks** or **OpenRouter** in Models & review. Provider choice is saved in the form and immutable job configuration. Databricks reads `DATABRICKS_AI_KEY`, `DATABRICKS_BASE_URL`, and `DATABRICKS_MODEL` from the server `.env`; the configured model is shown in the form. The configured AI Gateway base `/ai-gateway/mlflow/v1` is queried through `/chat/completions` with non-streaming responses. Claude Haiku 5.5 reasoning is disabled; its Chat Completions payload omits unsupported `response_format`. Prompts request JSON, and the pipeline validates responses before moving on. Credentials and private endpoint URLs are never returned to the browser. Both generation and metadata autofill use the selected provider, without automatic provider fallback.

Databricks token rates and USD charges are not supplied by this endpoint. The UI shows workspace billing and actual returned token counts, rather than applying OpenRouter rates or assuming free usage. Databricks jobs use supplied research, uploaded text, reference links and YouTube transcripts; paid OpenRouter web discovery is disabled. OpenRouter retains bounded web research and synchronous Standard/Flex options. Luna Flex is pinned to the Flex provider with standard-price fallback disabled.

Batch models are removed from selectors and the price API, rejected for new jobs, and cannot be resumed. Existing Batch records remain for history and billing reconciliation. A stopped local job does not cancel an already accepted provider batch; OpenRouter currently has no cancellation endpoint, so it may still complete and be billed. Loading an old configuration removes its Batch suffix before starting fresh. Requests remain sequential.

Choose 1–4 review passes. Each pass checks all chapters; only chapters with major issues are rewritten. The workflow stops reviewing early when there are no major issues. If the budget is exhausted, a final corrective rewrite is flagged for manual review. Fewer passes usually reduce cost but provide fewer opportunities to find and fix problems.

The estimate uses planning/target pages, brief/upload character counts, assumed source sizes, repeated prompt context, full review/rewrite cycles and model token rates. Actual length, source sizes, conditional rewrites and provider behavior change usage. Web charges, metadata autofill, taxes, credit purchase fees and hosting are outside this estimate. The workflow shows the sum of completed generation calls' provider-reported costs; unavailable/pending charges are not a final invoice. Confirm billing in OpenRouter.

## Operations

The ignored, permission-restricted `.env` holds `OPENROUTER_API_KEY` and the Databricks token, base URL and model variables. Never put it in frontend code or commit it. The deployment script passes it to both `nxflo-portal-api` and `nxflo-generator-worker`. Dependencies and fonts are installed in `Dockerfile.portal`. Both containers share the private data volume; nginx exposes only authenticated API routes. Download paths are controlled server-side and responses use private cache headers. HTML escapes model content, embeds only uploaded images and restricts scripts/assets through CSP; PDF rendering cannot fetch remote assets.

The worker is a separate restartable container using a process lock to prevent duplicate workers. Stage checkpoints and cached model responses resume interrupted jobs. If a submission is interrupted before its remote ID/response is saved, the job fails with a billing-uncertainty message instead of automatically resubmitting. Check the selected provider’s activity before creating a replacement. A heartbeat distinguishes an offline worker from a queued provider batch. Only one local job runs at a time.

Build and deploy with `bash 1_build_docker.sh` followed by `bash 2_deploy_docker.sh`. Database backups are created before deployment. Generated artifacts remain in `/data/generated/<job>/` in the Docker volume; a database-only backup does not include these files, so back up the volume for disaster recovery. Tests cover API authorization, persistence, cancellation, output downloads, graph review loops, actual PDF export, provider caching/Batch polling, DNS restrictions, chart evidence, and desktop/mobile workflow interactions.

## Company and team attribution

New configurations default to **Nexusflow Inc.**, website **https://www.nxflo.com**, and **Research Team at Nexusflow Inc.** with **research@nxflo.com**. Existing custom company names and logos remain saved. The owner can choose no team attribution, add/edit/remove up to 20 teams and their contact emails, or select a saved team. The selected team/email and company website appear on the cover and in a Document enquiries section near the end of both HTML and PDF. Saving revisions uses the current contact directory; earlier PDF contacts and revision-history rows remain immutable.

## Waiting, deadlines and recovery

Blocking network and PDF operations run in disposable child processes. The parent checks cancellation and updates heartbeat/waiting status at least every five seconds. A wall-clock deadline stops a request even if the provider continuously sends keepalive bytes: 90 seconds for optional web research, 180 seconds for model/Batch submission calls, 45 seconds for Batch status checks and individual reference downloads, 60 seconds for YouTube transcripts, and 120 seconds for PDF export. Network inactivity timeouts remain an additional safeguard.

The workflow distinguishes computing, waiting for a response, provider Batch queue time, and a missing worker heartbeat. Waiting messages show elapsed time and the maximum request duration. Batch progress shows the provider-reported status and completed/total requests; a completed HTTP status check does not imply completed Batch work. Transient read-only Batch status failures retry after one minute using the saved Batch ID. Paid submissions are never retried automatically after an uncertain outcome. Batch IDs are opaque safe identifiers and may use either hyphens or underscores.

Batch waiting details include elapsed provider time, the provider's deadline, failed/completed request counts, and the last successful check. Processing continues with the browser closed. **Check batch now** requests an earlier read-only poll of the existing batch; it never creates a replacement batch or switches models.

Temporary failures with accounted-for submissions retry automatically after 30, 120 and 300 seconds. HTTP 429 rejections can be retried because the provider rejected the request; a network timeout or HTTP 5xx during a paid submission has an uncertain outcome and is held for billing reconciliation instead. The retry budget resets after a completed workflow step. Accepted batches keep their original ID during status-check retries and worker restarts. Received raw model responses are saved before validation so parser failures can be repaired without repeating the paid request.

Failed or cancelled jobs can be resumed from the workflow or Document versions using **Resume generation**. This resumes the same job, configuration, version, checkpoint and cached responses; it does not create a revision. Owner authentication and CSRF checks apply, only one job can run at a time, and repeated resume requests are idempotent. Cancelled jobs never restart automatically. Jobs with an unknown paid submission outcome cannot be resumed until that submission is reconciled; the UI explains the hold instead of risking duplicate charges. Automatic retries stop after three failed attempts and leave the job available for investigation or manual resume.

The workflow timer counts total elapsed time from the saved job creation time, including queue time and interruptions, across refreshes. It updates every second and freezes when the job finishes or stops. Standard processing shows an approximate remaining-time and finish-time range based on source chunks, chapter count and review passes. These are planning assumptions, not measured provider throughput or completion guarantees. Flex adds an unbounded capacity-queue caveat. Batch has no reliable whole-document ETA; the UI shows the current stage's provider deadline and explicitly labels its finish time unknown. The 10-minute target is highlighted when exceeded; no paid requests are duplicated, models switched, or sequential processing changed to meet it.

If optional web research fails or exceeds its deadline, generation continues using the supplied brief, uploaded documents and available references. A source-coverage warning appears in the output and the finished document is marked for review. Existing web-search responses are reused when resuming jobs across upgrades.

## Web-research spending limit

Web research is capped at **US$0.30 per document/version**, covering the search fee, the search-notes model call and a conservative allowance for BYOK/platform fees. The saved `web_budget_usd` can be reduced or set to zero; the API rejects values above 0.30. Source summarization, drafting, review, metadata autofill and taxes are separate from this web-research allowance.

Native web-search loops are disabled. Each job permits one paid Parallel Turbo query with at most five results, followed by a Luna Flex response capped at 1,800 output tokens and with model tool calls disabled. The provider is pinned to Flex with no fallback. Before submitting, the worker verifies the live model catalog, applies provider input/output price ceilings and reserves enough for the entire advertised model context at conservative rates, capped output, the search fee, and 10% fee headroom. For the verified 1,050,000-token context, the conservative reservation is US$0.291335; actual small searches are much cheaper. If current pricing/context cannot be verified, the bound exceeds the limit, or a previous submission has an uncertain outcome, no new paid search is sent. A timeout never releases an uncertain reservation or triggers an automatic paid retry. Existing research is reused on resume.

Cost records now retain OpenRouter credit charges separately from `upstream_inference_cost` for BYOK. The reported total adds the provider amount only when BYOK is true, avoiding double-counting ordinary OpenRouter inference. Missing provider costs remain unverified; generation IDs are retained and read-only billing metadata is queried when needed. The UI shows the breakdown and billing reference. Historical native-search charges predate the limit and cannot be reversed by changing the setting.

Planning estimates include a separate bounded-search allowance, reference-link source-volume assumptions and per-source summary overhead. Once collection finishes, observed source characters/chunks replace assumptions for the matching form, and reconciled web charges replace estimates. These are usage estimates rather than a spending cap for the whole document.

### Deployment recovery

The worker drains on SIGTERM: it finishes the current bounded request, stores its result and billing metadata, then pauses at a durable request or graph boundary. Deployment waits for that exit without force-killing the worker. The replacement reuses completed responses and resumes the saved checkpoint. The first upgrade from a worker without draining refuses to interrupt running or queued jobs. An already lost response still requires provider reconciliation or explicit authorization before repeating its request.
